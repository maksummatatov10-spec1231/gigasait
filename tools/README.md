# tools/ — импорт реальных товаров (v3: Wildberries + Яндекс Маркет + Ozon)

## Зачем
Сайт статический (открывается двойным кликом по `index.html`), поэтому товары должны лежать
рядом с ним: картинки, описания, цены. Скрипт `import_all.py` скачивает 500 реальных товаров
(20 категорий × 25) и раскладывает их по папкам, а сайт читает готовый `marketplace/js/products.js`.

## Почему «v3» и что изменилось
У v2 (`import_wb.py`) был один способ — поиск `search.wb.ru`. С обычного домашнего IP он отдаёт
**429 Too Many Requests почти сразу и надолго** → 0 товаров. Теперь способов **восемь**, и скрипт
автоматически переключается на следующий, как только текущий начинает блокировать:

| # | Способ | Что это | Лимиты |
|---|--------|---------|--------|
| 1 | `wb.cards`  | `card.wb.ru` — карточки по списку артикулов (`wb_seed_ids` в конфиге, `tools/ids.txt`) | почти нет |
| 2 | `wb.recom`  | `recom.wb.ru/personal/…/search` — «персональный» поиск WB, отдаёт те же товары, что обычный | слабые |
| 3 | `wb.seller` | `catalog.wb.ru/sellers/v4` — весь ассортимент проверенных продавцов (`wb_sellers`) | слабые |
| 4 | `wb.catalog`| `catalog.wb.ru/catalog/<shard>/v4` по subject-id (subject/shard берутся из меню WB сами) | средние |
| 5 | `wb.search` | `search.wb.ru` v5/v4/sng (ротация) — обычный поиск, идёт последним | жёсткие |
| 6 | `ym`        | `market.yandex.ru/search?text=…` и `/category/<slug>` — HTML, внутри JSON SchemaOrg | капча после ~30–60 стр. |
| 7 | `oz`        | `ozon.ru/api/composer-api.bx` — **только с cookies браузера** (`--cookies`) | антибот |
| 8 | CDN WB      | `basket-NN.wbbasket.ru` — описания, характеристики и фото WB | нет |

Каждый способ — отдельный «предохранитель»: пауза между запросами (0.5–2 с, множитель `--delay`), после блокировки
он отдыхает 45–600 с, а очередь переходит к следующему способу/сайту. Пустая HTML-страница
вместо JSON и капча Яндекса тоже считаются блокировкой.

## Запуск на Windows
1. Установи Python 3.8+ (python.org, галочка *Add to PATH*). Библиотеки не нужны.
2. Двойной клик по `tools/import_all.bat` — или в консоли:
```
cd gigasait\tools
python import_all.py                         # всё: 500 товаров, WB → Яндекс → Ozon
python import_all.py --source ym             # только Яндекс Маркет
python import_all.py --source ym,wb          # Яндекс первым, WB добирает
python import_all.py --cat food --limit 2    # быстрая проверка (2 товара на подкатегорию)
python import_all.py --delay 2               # вдвое медленнее, если IP уже «под колпаком»
python import_all.py --cookies cookies.txt   # cookies из браузера (обязательно для Ozon)
python import_all.py --proxy http://user:pass@host:port
python import_all.py --build-only            # только пересобрать products.js
```
Полный импорт занимает **~5–15 минут** (если ловишь много 429 — `--delay 2`). Скрипт можно прерывать `Ctrl+C` и запускать
снова — скачанное не перекачивается, недостающее добирается. По умолчанию делает до 3 проходов:
второй добирает категории, где первый набрал меньше нормы.

### cookies (для Ozon, помогает и WB/Яндексу)
Расширение «Get cookies.txt LOCALLY» (Chrome/Firefox) → открыть ozon.ru / wildberries.ru /
market.yandex.ru → экспорт → `cookies.txt` → `--cookies cookies.txt`. Формат Netscape распознаётся
сам, домены раскладываются по сайтам. Можно и просто строку `ozon: a=b; c=d` в текстовом файле.

### свои артикулы
`tools/ids.txt`: строка = категория сайта + артикулы или ссылки WB через пробел.
Они качаются первым способом `wb.cards` (без лимитов) — быстрый способ добить нужную категорию.

## Что получается
```
marketplace/products/<категория>/<id>/     (id WB — число; Яндекс — ym123…, Ozon — oz123…)
    1.webp 2.webp 3.webp     фото (WB — до 3, Яндекс — 1 с выдачи, Ozon — что было в выдаче)
    product.json             все поля
    описание.txt             то же читаемым текстом
marketplace/js/products.js   единый каталог (window.MARKET_PRODUCTS), страны RU/KZ/BY/UZ/KG по кругу
```
`product.json`: `id, title, brand, category, subcategory, tags, price, oldPrice, rating, reviews,
country, stock, isNew, colors, supplier, description, specs{}, images[], source{site,url,imported}`.
`source.site` = `wildberries` | `yandex` | `ozon` — сайт показывает ссылку на оригинал.

Служебные файлы (в .gitignore): `.basket_cache.json` (корзины CDN WB), `.wb_menu.json` (меню WB),
`.import_state.json` (id без карточки/фото, чтобы не пробовать снова).

## Конфиг `import_config.json`
* `per_category` (25), `max_images` (3), `image_size` (`c516x688`).
* `categories` — категория сайта → подкатегория → запрос. Варианты через `|`: первый — основной поисковый запрос, остальные — дополнительные запросы и синонимы для проверки названия (`"парфюмерная вода|духи|туалетная вода"`). Минус-слова через `-слово` отсекают аксессуары и подделки под запрос: `"смартфон -чехол -стекло"`, `"кровать двуспальная -ламели -наматрасник"`.
* `wb_seed_ids` — проверенные артикулы WB по категориям.
* `wb_sellers` — ID продавцов WB (техника/электроника): `catalog.wb.ru/sellers/v4?supplier=…`.
* `ym_slugs` — подкатегория → слаг категории Яндекс Маркета (необязательно).

## Проверка соответствия (v3.2)
«Личный» поиск WB (`wb.recom`) без подходящей категории отдаёт персональную ленту — футболки, диффузоры,
влажные салфетки под видом «кофемашин». Поэтому теперь **каждый найденный товар проверяется**: слова
запроса (или синонимов через `|` в конфиге) должны быть в названии, либо WB сам отнёс товар к нужной
категории (`subjectId`). Что не прошло — не скачивается; уже скачанный мусор удаляется при старте и при
`--build-only`, а недостающее добирается заново (в том числе с Яндекс Маркета).

## Дубли
Один и тот же товар не может лежать в двух категориях: перед импортом и при `--build-only` дубли
папок удаляются (остаётся копия, чьё название лучше подходит запросу подкатегории), а цвет-варианты
одного товара (общий `root`) не скачиваются повторно.

## Если всё равно 0 товаров
1. `--source ym` — Яндекс Маркет из браузерной сети обычно отдаёт 30+ страниц по запросу.
2. `--delay 3` и подождать 10–15 минут перед повтором (лимиты WB держатся ~10 мин).
3. `--cookies` из своего браузера — запросы становятся «как из браузера».
4. Мобильный интернет/другая сеть или `--proxy`.
5. В самом конце: дописать артикулы в `tools/ids.txt` — способ `wb.cards` работает даже тогда,
   когда всё остальное отдаёт 429.

## Передача каталога частями (`split_products.py`)
Если файлы можно загружать только до 25 МБ: двойной клик по `tools/split_products.bat` (или
`python split_products.py`, `--mb 20` для другого размера). Скрипт найдёт `marketplace/products`
и `marketplace/js/products.js`, нарежет их на `tools/parts/часть1.zip, часть2.zip, …` по ≤24 МБ.
Папки товаров не разрываются между частями, внутри сохранены пути `marketplace/products/...`,
поэтому распаковка всех частей в корень репозитория восстанавливает каталог целиком.

## Миниатюры (после импорта)
```
python3 tools/make_thumbs.py
```
Создаёт `thumb.webp` (≤420px) в папке каждого товара и дописывает поле `thumb` в `products.js`.
Сетка каталога грузит миниатюры (≈15 КБ) вместо полных фото (≈80 КБ) — страница открывается заметно быстрее.
